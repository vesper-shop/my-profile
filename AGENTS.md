# Repository Instructions

Read the maintainer documents under `docs/` before substantial changes. This file contains the
current rules for architecture, runtime boundaries, fallbacks, helper functions, and shared types.

## Project Overview

Personal website built as a React SPA with a Void/Hono backend on Cloudflare Workers. It includes multilingual social and story pages and an interactive terminal.

## Package Manager

This is a pnpm workspace. Use pnpm commands, not npm or yarn.

## Commands

```bash
pnpm dev       # Vite+ dev server with Void and the Cloudflare runtime
pnpm build     # Production build
pnpm deploy    # Production build and Cloudflare deployment
pnpm check     # Void codegen, formatting, lint, and TypeScript checks
pnpm lint      # Void codegen plus Vite+ lint
pnpm format    # Vite+ formatting
```

## Architecture

### Core stack

- **Vite+ 1.5** — dev server, build, lint, format, and checks
- **Void 1.6** — Hono integration, file-based server routes and Cloudflare packaging
- **React 19** — client-side SPA
- **TanStack Router** — file-based client routing; generates `src/routeTree.gen.ts`
- **TypeScript 7**
- **Tailwind CSS 4** — CSS-first configuration
- **Hono** — Worker request handlers

`vite.config.ts` installs `voidPlugin()`, the TanStack Router plugin, React, and Tailwind. Void uses the Cloudflare Vite runtime internally; there is no hand-written Worker entry point.

### Project layout

```text
.
├── routes/                 # Void file-based server routes
│   └── api/                # JSON and image API handlers
├── public/                 # Static assets, sitemap, and machine-readable profile files
├── server/lib/             # OG and presence helpers
├── src/                    # React SPA and TanStack Router pages
├── types/                  # Shared application types (@shared/*)
├── packages/ui/            # Shared UI, footer, and terminal
├── void.config.ts          # Void target, database, inference, Worker and Cloudflare bindings
├── void.lock.json          # Void-recorded Cloudflare resource state
└── .env                    # Local development values (gitignored)
```

Generated files:

- `src/routeTree.gen.ts` is generated by TanStack Router.
- `.void/` is generated by Void and ignored by Git.
- `dist/`, `.cloudflare/`, and `.wrangler/` are build artifacts.

Do not edit generated files manually.

### Server routing

Void derives the URL from the path under `routes/` and the HTTP method from named exports:

```ts
export const GET = defineHandler(...)
export const POST = defineHandler(...)
```

Do not add `.get` or `.post` to route filenames. Catch-all segments use `[...name].ts`.

Current routes:

| URL             | Handler                  |
| --------------- | ------------------------ |
| `/api/og/home`  | `routes/api/og/home.ts`  |
| `/api/presence` | `routes/api/presence.ts` |

`/sitemap.xml`, `/llms.txt`, and `/llms-full.txt` are static files under `public/` and bypass the
Worker in production.

### Frontend

`src/routes/` contains TanStack Router pages:

- `index.tsx` — home
- `social.tsx` — multilingual social links, follow policy, contact, and sponsorship
- `story.tsx` — story and Mapbox travel map

## Authentication

The site has no sign-in. Every Vesper app and site signs in with Vesper (noted-this.date).

## Environment and deployment

The site needs no secrets or environment variables.

- The `cloudflare` section of `void.config.ts` declares only resource bindings; Void rejects
  schema-declared server keys in `vars`.
- Application code reads environment values through `void/env` or `c.env`, never `process.env`.
- The public Mapbox token is a client-side constant; it is not part of the environment schema.

## Linting and formatting

Vite+ configuration lives in `vite.config.ts`:

- type-aware linting and type checking are enabled
- `dist/**` and `src/routeTree.gen.ts` are ignored
- formatting uses tabs

Use `void` for intentionally ignored promises when required by the linter. Avoid `any`.

## Local Rules

- Keep browser-only code in `src/`, Worker-only code in `server/` or `routes/`, and genuinely
  cross-runtime contracts in `types/`.
- Do not add a file to `types/` unless both browser and Worker code consume the contract.
- Do not add broad or speculative fallbacks. A `catch` block must have explicit recovery,
  translation, or cleanup behavior.
- Do not create one-line or one-call-site helper functions without a boundary or domain reason.
- Application UI uses the existing semantic tokens in `src/styles/tokens.css`. Do not replace the
  project theme or font stack when changing one feature.
